# Where this code comes from

The crates in this directory are a copy of part of Rune, a native GPU UI framework by Anomaly, published under the MIT licence (see `LICENSE` next to this file).

- **Repository:** `https://github.com/anomalyco/rune`
- **Branch and commit:** `dev` at `2b7dbf223b84b58bcfb1e5a9e92577b9244540dd` (2026-11-11)
- **Why a copy and not a dependency:** UniDTK owns its renderer. From the import on, this is UniDTK code; upstream changes are read and taken by hand, never pulled. The plan is [the native desktop host on Rune](../../docs/dev/plan-rune-host.md).

## What was taken

| Crate | What it is |
| :--- | :--- |
| `rune` | The framework: elements, runtime, layout, text, renderer, windows, input |
| `rune-motion` | The animation runtime: springs, retargetable tracks, presence, matched geometry |
| `rune-taffy` | The compact layout store over Taffy |
| `rune-staging` | Per-frame GPU uploads through reused staging memory |
| `rune-fx` | Effect layers: glow, pulses, motion blur, distortion |
| `rune-light` | Lighting: soft shadows, bevels, god rays, global illumination |
| `rune-notify` | System notifications (toast on Windows) |
| `rune-i18n` | Message catalogs checked at compile time |
| `procwatch` | The process's own memory and CPU, watched from inside |
| `rune-perf` | Bounded local performance recording |

Not taken: `rune-kit`, `rune-mermaid`, `rune-highlights`, `rune-luau`, `rune-knobs`, `rune-mac`, `rune-ref`, `rune-register`, the themes, the examples, the site, the research notes, and the vendored `wgpu-hal` patch.

## Changes made to the copy

1. **Import.** Each crate's `Cargo.toml`, `src/` and embedded assets were copied unchanged. The `tests/`, `examples/` and `benches/` directories were not copied.
2. **Workspace.** The crates are members of the UniDTK workspace. They inherit `edition`, `license` and the lint table from the root `Cargo.toml`, which repeats upstream's values; `clippy.toml` sits in this directory so that it applies to these crates only.
3. **Tests removed.** The `[[test]]`, `[[example]]` and dev-dependency sections were removed from the manifests, every in-source test file (`*_tests.rs`, `tests.rs`, `src/**/tests/`) was deleted together with the `mod` line that declared it (178 files), and each crate sets `[lib] test = false, doctest = false`, so the inline `#[cfg(test)]` blocks that remain are never built. Many of these tests needed a real GPU adapter or fonts from upstream's `opencode` theme, which is not taken.
4. **Other platforms removed.** UniDTK runs only on `x86_64-pc-windows-msvc`, so the `rune` crate lost every module that is never compiled there: a module was removed when the `#[cfg]` on its `mod` line is false for `target_os = "windows"`, `target_arch = "x86_64"`, `target_vendor = "pc"` with `test` off. That is 50 `mod` declarations in 25 files (106 lines with their attributes) and the 86 source files behind them: the macOS, iOS and Apple-vendor code (the native Metal backend `gpu/metal/`, AppKit windows, menus, popup menus, clipboard, drag-out, native surfaces, system materials, screen recording, video through AVFoundation, spelling, shortcuts, display link, embedding, the NSAccessibility adapter), the Linux code (X11, Wayland layer shell and shortcuts, the D-Bus tray, the desktop portals for file dialogs and appearance, the AT-SPI adapter) and the wasm32 code (`platform/web/`, the web clipboard, task and cursor images, the page clock), and `tooling/test_alloc.rs` under `#[cfg(test)]`; modules gated `any(test, <another platform>)` went too, since tests are never built. Also removed: the two `include!`d tables only those modules read (`gpu/metal/builtin_table.rs`, `render/uber/windfoil_hash.rs`), the three `wasm-bindgen` JavaScript files of `platform/web/`, and the seven precompiled Apple shader libraries `src/*.metallib` (about 1.8 MB), whose remaining `include_bytes!` sit behind `cfg(target_os = "macos")`. In all 98 files and 17,178 lines of source. In `Cargo.toml` the six dependency sections for `cfg(target_vendor = "apple")`, `cfg(target_os = "macos")`, `cfg(target_os = "linux")`, `cfg(target_arch = "wasm32")`, `cfg(all(unix, not(target_os = "linux")))` and `cfg(all(unix, not(target_os = "macos"), ...))` were removed; the features `metal-backend`, `ogg-audio` and `dbus`, whose optional dependencies were all in those sections, were removed and dropped from `default`; `accessibility` keeps only `accesskit_windows`, and `native-file-dialog` keeps only `rfd`. Inline code for other platforms in the files that stay was not rewritten: 616 `#[cfg(...)]` attributes in 107 files (316 of them `#[cfg(target_os = "macos")]`) and 75 `cfg!(...)` expressions are false on Windows, so their blocks, some of which name removed modules and dependencies, are compiled out. The cfg predicates that tested `feature = "metal-backend"` or `feature = "dbus"` named a feature the manifest no longer declares, so each predicate was replaced with `any()`, which is always false — the value the absent feature had — so every `all`, `any` and `not` around it evaluates exactly as before on Windows, and `cargo check` reports no `unexpected_cfgs`. The three `private_interfaces` warnings that remain come from upstream unchanged.
5. **Line ends.** The repository's `.gitattributes` marks `core/rune/**` as `-text`, so a Windows checkout with `core.autocrlf` keeps these files as upstream wrote them, with LF. The renderer takes its precompiled DX12 uber shader (`uber.vs.dxbc`, `uber.fs.dxbc`) only while the WGSL source hashes as `render/uber/dxbc_hash.rs` records, and that hash is of the LF text: with CRLF it compiled the shader through FXC on every launch, 56.6 s on an Iris Xe laptop before the first frame (`renderer.begin` to `renderer.ready`, session 138).
6. **Two methods gated.** `CommitMeter::handler` and `CommitMeter::frame_ends` (`tooling/perf_warn/commits.rs`) are called only under `#[cfg(debug_assertions)]`, so a release build of the app warned that they are never used; they carry the same `#[cfg(debug_assertions)]` as their callers now.
7. **A smaller view heap.** `Gpu` asks its device for at most 65,536 non-sampler bindings (`MAX_VIEW_DESCRIPTORS` in `render.rs`) instead of `wgpu`'s default of 1,000,000. `wgpu-hal`'s DX12 backend makes its shader-visible CBV/SRV/UAV heap that large, and the driver commits and zeroes it: with Intel's 64-byte descriptors it was a 61 MB private region, fully resident, half of the host's 124 MB Working Set (session 138).
8. **Desktop child-window occlusion, true-alpha readback, wait-cancelled telemetry, and key injection.**
   - `platform/win32/occlusion.rs`: root-aware Z-order tracking (`GA_ROOT`) for `WS_CHILD` hosts under Explorer desktop layers (`Progman`/`WorkerW`/`SHELLDLL_DefView`/`SysListView32` excluded only when owned by `GetShellWindow()`'s PID), child-rect & `GetWindowRgn` intersection clipped to root monitor bounds, lock/UAC `OpenInputDesktop() == NULL` -> `Covered`, ignore third-party `WS_CHILD` `EVENT_OBJECT_DESTROY`, and `recheck()` helper wired through `WindowHandle::recheck_occlusion`.
   - `frame/surface_stats.rs` + `window/any_host.rs` + `overlay/any_host.rs`: expose `SurfaceCounts::wait_cancelled` (`StartCause::WaitCancelled` interruption count separated from deadline wakes).
   - `render.rs` + `drag_out/mod.rs` + `window/{handle.rs, events.rs, rs}`: add `readback_staging_layout` (`> 4 MiB` dedicated readback buffer threshold to avoid persistent DX12 general heap pinning, `MAX_READBACK_PIXELS = 16_777_216`), shared `unpremultiply_to_straight_rgba`, non-UI-stalling `WindowHandle::capture_rgba` (pre-validating viewport/layout/GPU format before settling stale trees and flushing clipboard/shell effects), and `InjectedKey` + `WindowHandle::{inject_key, inject_focus_lost}` with `Runtime::allow_injected_keys`.
   - `app.rs` + `frame/encoded.rs` + `runtime/frame.rs` + `window/{rs, spec.rs, draw.rs, any_host.rs, events.rs}`: add `App::on_tree_committed` / `WindowSpec::on_tree_committed` and `check_commit_transition` hooked across all commit/covered/offscreen paths, advance cold covered boots (`!rt.has_committed()`) once inside `covered_step`, and export `Runtime::has_committed`, `check_commit_transition`, and `covered_step` via `win32_telemetry`.
9. **`WindowOptions::no_redirection_bitmap` (Windows).** `window/spec.rs` forwards it to winit's `with_no_redirection_bitmap`. Without it winit enables DWM blur-behind on a transparent window (`on_create`) and the window keeps a GDI surface; for a transparent, click-through child of the desktop host the title bar of the frame it was created with stayed visible through the clear pixels (found live in session 141: `PrintWindow` of the window held a caption band, the `wgpu` readback did not). The overlay path already sets the same attribute (`overlay/lifetime.rs`).
10. **What the desk's widgets need of CSS (session 143).** Each is an addition; nothing upstream does changes.
   - `el/visual.rs`, `el/visuals.rs`, `runtime/paint/build.rs`, `runtime/commit/memo_reuse.rs`: `El::hover_fill`, `El::hover_border` and `El::hover_lift`, CSS `:hover` on the fill, the border colour and a `translate`, mixed on the element's own hover track (`El::hover` only paints over a fill, which cannot make a translucent button more transparent on hover). Lift is paint only: layout and hit testing keep the resting place. The memo comparison includes the three fields.
   - `edit.rs`: `TextEdit::max_chars`, HTML's `maxlength`: an edit keeps only what fits, a whole character at a time; text set in code is not cut. Pinned by a test in `core/desktop/tests.rs`, since this crate's tests are not built (item 3).
   - `tok.rs`, `text.rs`: `TextStyle::lh_normal`, CSS's `line-height: normal` (the font's ascent, descent and line gap, through parley's `LineHeight::MetricsRelative(1.0)`), stored as a negative line height so the type keeps its size. The page sets no line height on most of the menu's text, and Segoe UI's own is 1.33 of the size, not the 1.25 Rune assumes.
   - `rune-motion/src/transition.rs`, `scene/presence.rs`, `scene/travel.rs`: `Transition::curves`, an enter and an exit `Anim` that replace the presence springs, so an element appears and leaves on a CSS duration and easing (`opacity 220ms ease`, a keyframe `animation` on `expoOut`); `Transition::springs` clears them. Presence reads `Transition::enter_anim` and `exit_anim` where it read the springs.
   - `Cargo.toml`, `window.rs`, `window/events.rs`, `window/handle.rs`, `render/layers.rs`, `lib.rs`: `WindowHandle::gpu_memory`, fetched on the window's thread as `capture_rgba` is: `wgpu`'s internal counters of textures and buffers (the `counters` feature of `wgpu`, now on), the renderer's `LayerStats` with the spare targets it keeps for reuse (`spare`, `spare_bytes`, new), and the allocator's report by label. `udtk host frames` shows them (`gpu`), because on a GPU that shares system memory these are most of the host's private bytes. The report alone was not enough: `wgpu-hal` turns DX12 suballocation off on Iris Xe (`dx12/adapter.rs`), so every resource is committed and the allocator reports nothing there.
   - `window/events.rs`: an offscreen capture builds the view again when the runtime thinks its last frame current. A covered window steps frames without drawing, and a view that reads the clock (a morph's progress) is not stale to the runtime, so `udtk shot --host` of a covered desk showed an older frame than the state.
   - `runtime/elements.rs`, `el/element_info.rs`: `ElementInfo::shadow_extent`, how far an element's outer box shadows reach past its rect on each side (1.5 x the CSS blur, plus spread and offset). The desk host clips its window to a region for input (`SetWindowRgn`), and a region clips what the window shows too: with a fixed 16 pt margin, a 90 pt surface shadow was cut off.
   - `app.rs`, `window/lifecycle.rs`: `AppHandle::inspect`, a reader of the runtime that another thread queues like `update`: it runs on the UI thread when the window takes the requests, after the updates queued before it, even while the window is covered and draws nothing, and asks for no frame. `Requests` and `Shared` gained `S: 'static`, the bound `Runtime` already has. The host's inspector describes the committed tree through it when it made none on the last commits (a covered desk commits nothing to wait for).
   - `runtime.rs`, `runtime/paint/build.rs`, `runtime/elements.rs`: `drawn_commit`, the commit `drawn` was built after. `drawn` is rebuilt only when a frame is built, so after a commit with no frame (a covered window) it is indexed by the nodes before that commit; `Runtime::keyed_regions` (also added here, the cheap read of the rects a window region is made of) and `Runtime::elements` take a drawn rect only when no commit came since, and the scene's presented place otherwise; `keyed_regions` also joins the element's layout box (`target`), because a covered window commits without stepping its springs and an element that moved still stands, presented, at its old place. Upstream's own hit testing still reads `drawn` as it did.
11. **Order in an attached desktop window (Windows).** `window/spec.rs` forwards `skip_taskbar` to winit. `window/win.rs` uses the usual Rune reveal and first-frame cloak, while `platform/win32.rs` orders in a Win32 child with `SW_SHOWNOACTIVATE` and rechecks occlusion. Winit still caches the top-level style and its own show would overwrite `WS_CHILD`.
12. **A field hears why it lost focus (session 150).** `BlurCause` (`el/input.rs`: `Escape`, `FocusMove`, `Pointer`, `WindowLost`, `Unmount`) and `El::on_blur`: every path that leaves a focused field records the cause (`Action::Blur(<cause>)` from a pointer press, Escape, `set_focus_cause`, a field dropped by the new tree), and `Runtime::drain_blurs` runs the handlers once the frame's actions are done, so a handler sees the committed state and may move focus again. `Runtime::window_focus(false)` and the host's `inject_focus_lost` both deliver `WindowLost`. The kernel stamps each forwarded key with `INPUT_GENERATION` (`ControlMessage::InjectKey::input_generation`), and its `FocusLost` carries the counter too: the desk refuses a key whose stamp is older than the last loss (`core/desktop/host.rs`), so a key queued before the blur cannot type into the desk. `handle_set_desktop_input_focus` tells the two reporters apart (`crate::is_native_host()`): the page's DOM focus is filtered against the foreground, the native host's report is stored raw.
