# Unified Core Modules Motion (unicoremodmotion.md)

> **Статус документа:** Официальный архитектурный стандарт ядра UniDTK.  
> **Область применения:** Движок анимаций (`motion.js`), единый менеджер поверхностей (`surface-manager.js`), все виджеты, всплывающие окна, модалки, оверлеи и контекстные меню.

---

## 1. Фундаментальный закон двух типов объектов

Вся графическая подсистема UniDTK строго разделяется **ровно на два типа объектов**. Любые промежуточные гибриды или ad-hoc всплывающие блоки запрещены.

```
                     ┌────────────────────────────────────────┐
                     │             UniDTK Engine              │
                     └───────────────────┬────────────────────┘
                                         │
                 ┌───────────────────────┴───────────────────────┐
                 ▼                                               ▼
     ┌───────────────────────┐                       ┌───────────────────────┐
     │    1. ВИДЖЕТЫ         │                       │    2. ПОВЕРХНОСТИ     │
     │     (WIDGETS)         │                       │      (SURFACES)       │
     ├───────────────────────┤                       ├───────────────────────┤
     │ • Постоянно на столе  │                       │ • Открываются по клику│
     │ • Хранят координаты   │                       │ • Морфятся из хитбокса│
     │ • Drag & Drop / Resize│                       │ • LIFO стек закрытия  │
     │ (Плеер, Часы, Папки)  │                       │ (Эксплорер, Попапы, ТГ)│
     └───────────────────────┘                       └───────────────────────┘
```

### Тип 1. Виджет рабочего стола (`Widget`)
- **Определение:** Персистентная карточка, постоянно присутствующая на холсте `widgetsCanvas`.
- **Представители:** Круглый аудиоплеер (`mp3-player`), часы (`clock`), док Telegram (`telegram`), глиф-бар (`glyph-bar`). Именование в ранних версиях дока (`yt-music`, `games`/`notes`/`launcher`/`network`/`tools`) устарело; актуальные модули — `clock`, `explorer`, `glyph-bar`, `mp3-player`, `telegram`, `vpn`.
- **Свойства:** Обладают сохраненными координатами в `config.positions`, поддерживают перетаскивание (`setupDragReorder`), пересчет при смене экранов (`relayoutWidgets`), никогда не сбрасываются и не удаляются из DOM при закрытии других окон.

### Тип 2. Поверхность / Окно (`Surface`)
- **Определение:** Любое окно, панель, модалка, диалог или меню, открывающееся в ответ на действие пользователя.
- **Представители:**
  - Окно файлового менеджера Nothing Explorer (`#explorerOverlay`);
  - Попапы аудиоплеера: библиотека (`.music-library-popup`) и настройки (`.music-settings-popup`);
  - Панель выбора VPN-серверов в часах (`.vpn-server-menu`);
  - Модальные окна Telegram (пересылка сообщений, отправка файлов, просмотр фото в лайтбоксе);
  - Контекстные меню по правому клику (в проводнике и чатах).
- **Свойства:** Управляются **исключительно** через единый контракт ядра `SurfaceManager`, монтируются в единый координатно-безопасный портал `#shell-portals`, используют единый аппаратный морфинг границы и регистрируются в стеке LIFO.

## 2. Жесткие архитектурные правила движения (Motion Guardrails)

### Правило 2.1: Полный запрет захардкоженных миллисекунд
- **Категорически запрещено** писать фиксированные тайминги анимаций в CSS и JS (`140ms`, `220ms`, `340ms`, `400ms`, `setTimeout(..., 220)`).
- Длительность анимации $T$ **рассчитывается динамически на лету** математической функцией `calculateDuration(targetW, targetH, originW, originH)` в `motion.js` на основе физического размера или дельты расширения границы ($\Delta d = \sqrt{\Delta W^2 + \Delta H^2}$):

$$T(\Delta d) = \left[ T_{\min} + (T_{\max} - T_{\min}) \cdot \frac{\ln\left(1 + \frac{\Delta d}{d_0}\right)}{\ln\left(1 + \frac{d_{\max}}{d_0}\right)} \right] \times \text{currentScale}$$

Где:
- $T_{\min} = 240\text{ ms}$ (микроменю, контекстные списки);
- $T_{\max} = 440\text{ ms}$ (полноэкранный Explorer);
- $d_0 = 100\text{ px}$, $d_{\max} = 1600\text{ px}$;
- $\text{currentScale}$ — глобальный множитель скорости системы из `setMotionScale()`.

### Правило 2.2: Аппаратный морфинг границы из хитбокса (Origin Clip-Morphing)
- **Запрет зума содержимого (`scale`):** Контент окна (текст, шрифты Ndot/Inter, пиктограммы, обложки) **строжайше запрещено масштабировать через `transform: scale()`**. Масштабирование шрифтов размывает субпиксельный рендеринг DirectWrite в WebView2.
- **Морфинг границ:** Окно сразу монтируется в своих финальных пиксельных габаритах (1 Layout-проход, 0 reflow при анимации). Граница контейнера разворачивается аппаратно на GPU через `clip-path: inset(top right bottom left round radius)`:
  - $t = 0$: маска сжата в точные координаты и скругления кнопки/хитбокса вызова (например, в сектор `zone-top` плеера со скруглением $R=75\text{px}$, точно повторяя окружность винила);
  - $t = 1$: маска экспоненциально раскрывается до `inset(0 0 0 0 round 24px)`.
- **Проявление контента:** Контент проявляется мягким `opacity: 0 -> 1` и микросдвигом $\Delta y = 6\text{–}8\text{ px}$ на 65% завершения движения границы.

### Правило 2.3: Мгновенный плавный реверс (Seamless Animation Reversal)
- Запрещено использовать `setTimeout` для финализации анимаций.
- Если во время раскрытия окна (например, на 60 мс из 260 мс) пользователь нажимает `Escape` или кликает мимо — анимация **не зависает и не дергается**. Вызывается `animation.reverse()`, и окно плавно, прямо из этой промежуточной точки, закрывается обратно в хитбокс за те же 60 мс.

### Правило 2.4: Единый LIFO-стек закрытия (Last In, First Out)
- Все открытые поверхности регистрируются в массиве ядра `SurfaceManager.activeStack`.
- Клавиша `Escape` и клик мимо окна перехватываются единым глобальным слушателем ядра.
- Нажатие `Escape` закрывает **СТРОГО одну, самую верхнюю поверхность**:
  $$\text{Контекстное меню} \xrightarrow{\text{Esc}} \text{Модалка} \xrightarrow{\text{Esc}} \text{Эксплорер} \xrightarrow{\text{Esc}} \text{Сворачивание виджетов}$$
- Запрещено закрывать фоновые окна или виджеты, пока открыта модалка верхнего уровня.

### Правило 2.5: Защита координат и целостности виджетов
- Любые манипуляции с поверхностями и анимациями **ни при каких условиях не должны сбрасывать `config.positions`** или вызывать деструктивный сброс DOM (`innerHTML = ""`) на `widgetsCanvas`.

## 3. Пошаговый план инженерной реализации

### Этап 1. Ядро движения и математика динамических таймингов (`motion.js`)
1. Реализовано в `core/ui/motion.js`:
   - Функция `calculateDuration(width, height, originRect)` по логарифмической физической формуле.
   - Полный канон токенов (EASINGS в `core/ui/motion.js`): `--ease-standard` `(0.4,0,0.2,1)`, `--ease-spring` `(0.34,1.56,0.64,1)`, `--ease-expo`/`--ease-expo-out` `(0.30,0.95,0.35,1.00)`, `--ease-expo-out-rev`/`--ease-surface-exit` `(0.38,0.05,0.45,1.00)`, `--ease-snap` `(0.18,1.04,0.22,1)`, `--ease-content` `(0.25,1,0.5,1)`, `--ease-smooth` `(0.25,0.1,0.25,1)`, `--ease-item-in` `(0.16,1,0.3,1)`.
   - Поддержку бесшовного `reverse()` для Web Animations API.

### Этап 2. Диспетчер поверхностей ядра (`surface-manager.js`)
1. Создан в `core/ui/surface-manager.js`:
   - LIFO-стек открытых окон (`activeStack`);
   - Единый перехватчик `Escape` в capture-фазе с гарантией закрытия ровно одного верхнего окна;
   - Единый обработчик `pointerdown` для закрытия по клику мимо;
   - Функция `openSurface(element, options)`: расчет координат хитбокса, запуск аппаратного `clip-path` морфинга границ и отложенного проявления контента;
   - Функция `closeSurface(element)` с плавным реверсом в хитбокс;
   - Каноническая шкала слоев `--z-surface-*`.

### Этап 3. Перевод попапов плеера (Библиотека и Настройки)
1. Подключить попапы плеера (`.music-library-popup` и `.music-settings-popup`) к `surface-manager.js`:
   - При клике на `zone-top` граница разворачивается из верхнего сектора круга ($R=75\text{px} \to 24\text{px}$);
   - При клике на `zone-bottom` — из нижней тач-зоны;
   - Контент списка плейлистов плавно фейдится без искажения обложек и текста;
   - Проверка нажатия `Escape` посреди раскрытия — мгновенный обратный ход в хитбокс.

### Этап 4. Подключение Explorer, модалок Telegram и контекстных меню
1. Перевести полноэкранный оверлей Explorer (`#explorerOverlay`) на регистрацию в `surface-manager.js`:
   - Замена старого `scale(0.92) + translateY(12px)` на аппаратное разворачивание границ с динамическим таймингом;
   - Контекстные меню проводника и Telegram регистрируются как поверхности верхнего слоя и закрываются первыми по `Escape`.
2. Ликвидация дублирующих обработчиков клика в `vpn-panel.js` и устранение утечек памяти.

### Этап 5. Сквозная верификация и замеры
1. Запуск приложения и сквозной замер через CLI-мост (`udtk`): `udtk doctor` (в т.ч. `-simulate`), `udtk logs --level ERROR`, `udtk shot`.
2. Запуск UniDTK через Task Scheduler `UniDTK` (`schtasks /run /tn UniDTK`) или `udtk run`, замер метрик:
   - `udtk doctor --quick` — целостность DLL, IPC и задач;
   - `udtk logs --level ERROR` — проверка нулевого уровня ошибок;
   - `udtk shot` — обязательный визуальный аудит в свернутом, полуоткрытом и полностью открытом состояниях.
3. Фиксация результатов сессии в `docs/architecture.md`.

## 4. Зафиксированный бэклог доработок и полировки (Backlog — Выполнено на 100%)

Все 8 замечаний успешно реализованы, протестированы и верифицированы в рантайме WebView2:

1. **Калибровка скорости попапов плеера** — [РЕШЕНО]:
   - В `openMusicPopup` (`modules/mp3-player/ui/widget.js`) явно передан токен `duration: "layout"` (340ms по канону `DURATIONS`), синхронизирующий время разворачивания с физическими папками стола.
   - Смещение контента `content` в `surface-manager.js` смягчено с `0.65` до `0.45` от общей длительности, предотвращая внезапное появление текста и обложек на последних миллисекундах.
2. **Закрытие попапов плеера по клику на шапку** — [РЕШЕНО]:
   - Вся область `.music-popup-header` наделена делегированным обработчиком клика с `closePopupElement(popup)`.
   - Клики по интерактивным элементам управления внутри шапки фильтруются (`e.target.closest("button, input, select, a, [data-prevent-close]")`), кроме крестика закрытия `.music-popup-close`.
   - В стили добавлен `cursor: pointer` и `user-select: none`.
3. **Верстка списка серверов VPN в виджете часов** — [РЕШЕНО]:
   - Найдена корневая причина: `_finalizeClose` в `surface-manager.js` сохранял `element.style.display = record.prevDisplay || "none"`. При изначально пустом инлайн-стиле элемент получал `"none"`, и при повторном открытии срабатывал fallback `display = "flex"`.
   - В `_finalizeClose` реализовано сохранение пустой строки `""`, в `.vpn-server-menu` CSS жестко зафиксировано `display: flex; flex-direction: column;`, а в `vpn-panel.js` явно передается `display: "flex"`.
4. **Оптимизация открытия виджета Telegram** — [РЕШЕНО]:
   - Ликвидирован 400ms параллельный CSS-переход геометрии с layout thrashing.
   - Реализована 1-pass верстка: карточка мгновенно выставляется в целевой размер, а границы разворачиваются аппаратным WAAPI GPU-морфингом `clipPath: inset(...)`.
   - На карточку добавлен `overflow: hidden !important;`, скрывающий текст и элементы интерфейса за границей виджета до завершения раскрытия.
   - В `onfinish` и `oncancel` встроена полная очистка `clipPath = ""` для предотвращения размытия субпиксельного антиалиасинга шрифтов DirectWrite ClearType в WebView2.
5. **Анимации списка аккаунтов Telegram (`.tg-account-dropdown`)** — [РЕШЕНО]:
   - Выпадающий список переведен на `surfaceManager.openSurface(dropdown, ...)` с токенами `origin: accountBtn`, `originRadius: "8px"`, `targetRadius: "12px"`, `display: "flex"`.
   - Удалены самодельные `setTimeout(180)`, размывающие масштабные трансформации `scale(0.96)` и утекающие слушатели кликов на `document`.
6. **Анимации внутренних переходов и выделения** — [РЕШЕНО]:
   - В Explorer удалены размывающие масштабирования `scale(0.98)` / `scale(0.96)` из `.file-area.transitioning` и `@keyframes fileAppear`, исключена искусственная задержка в 2 rAF при навигации.
   - В `telegramSetActiveChat` добавлен аппаратный микрофейд списка сообщений `.tg-messages` без дергания layout.
   - В Explorer реализована аппаратная рамка группового выделения (Marquee Selection) с предрасчетом AABB на старте движения (кэширование 120 FPS), гистерезисом 4px, компенсацией скролла и очисткой выделения по клику на фон.
7. **Закрытие папок-виджетов по клику на пустое пространство стола** — [РЕШЕНО]:
   - В `shell-core.js` внедрен глобальный слушатель `setupDesktopOutsideClickHandler()` с порогом перемещения мыши `< 6px` (dead-zone от случайного закрытия при перетаскивании).
   - Интегрирована проверка приоритета LIFO: если открыты контекстные меню или модалки `surfaceManager`, рабочий стол не перехватывает клик.
8. **Правило взаимного исключения развернутых виджетов (Widget Mutual Exclusion)** — [РЕШЕНО]:
   - Устранена геометрическая утечка невидимого фантомного блока $400\times 400\text{px}$: `collapseSingleWidget` и `collapseActiveDesktopWidget` принудительно сбрасывают `width` и `height` в компактные размеры (`pos.w || 340`, `pos.h || 64`).
   - Хаотичные таймеры `setTimeout(400)` заменены на отменяемые `card._collapseTimer` (320ms).
   - Введен монотонный счетчик `expandSequence`, защищающий от асинхронных гонок рендера ярлыков.
   - В `relayoutWidgets()` добавлена защита активного развернутого виджета от затирания координат при ресайзе экрана.
